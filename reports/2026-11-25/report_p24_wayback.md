# P24–P26 报告：选择当时可见的 likes / downloads / 门控，以及当时版本的模型卡

日期：2026-11-25。结果表在 `results/tables/v2/p24_wb_coverage.md`、`p26_hub_shares.md`、`p26_hub_coef.md`（全部系数在 `p26_hub_coef_all.csv`）。

## 1. 要回答的问题

快照中的 `likes`、`downloads`、`trendingScore` 是 2025-07-12 的值，会泄露未来信息，所以主结果没有使用（note2 §1）。候选模型的卡片文本（P18 `txt_sim`）和 model-index 分数（P14 `bench_z`）也取自快照版卡片。本轮回答两个问题：

1. 把开发者当时在 Hub 页面上看到的 likes、downloads 和门控状态加入流行组后，"流行 ≫ 适合"的结论会不会变？
2. 把卡片换成选择当时的版本后，需求匹配和质量的份额会不会变？

## 3. 设计：枢纽市场

- **样本：** 只保留被选父模型属于目标集合的首次采纳，并把候选集也限制在目标集合内。共 116,969 / 133,216 次选择（88%），平均每次 39 个候选；训练集 103,831 次选择。
- **为什么这样限制：** 条件 logit 满足 IIA，按固定规则限制候选集不改变系数的含义，log q 修正保持不变。所有设定都在同一样本上估计，所以设定之间的差别只来自特征本身。
- **为什么不在全候选集上做：** 目标集合之外的候选（130 万个）基本没有 Wayback 抓取。如果对它们加"缺失"指示变量，这个变量实际上就成了"是不是枢纽"的指示变量。
- **当时信号的取法：**
  - likes、downloads、门控：取选择时刻之前、且不早于 60 天的最近一次抓取；没有则记为缺失（填 0 并加指示变量）。
  - 抓取覆盖：75% 的候选行、77% 的被选行有可用值。
  - 门控状态（需要人工或自动审批）计入流行组中的"可得性"部分，和主结果的分组口径一致。

## 5. 结论

1. **主结果对"流行信号是否测错"稳健。**
   - 加入当时页面上的 likes、downloads 和门控后，流行份额从 93.64 变为 93.69，适合/流行比值从 0.0626 变为 0.0621。对数似然只提高 519，约占总提升的 0.3%。
   - degree 和 recent30 的系数几乎不变。网络算出的流行度已经包含了页面信号的绝大部分信息。
2. **当时的页面信号本身的作用：**
   - likes 有独立的正向作用。likes 翻倍，被选的几率约提高 5%（e^{0.07·ln2}）。
   - 控制 degree 和 recent30 后，downloads 几乎没有额外作用。
   - **门控有明显的负向作用：** 需要申请权限的模型被选的几率低约 27%（e^{−0.31}）。这是 README 中"可得性：免门控"的第一个直接估计。
3. **快照值会高估 downloads 的作用。** 用快照 downloads 时系数是 0.122（z = 41），用当时的 downloads 只有 0.005。说明快照值主要反映了选择之后积累起来的流行，印证了 note2 §1 不使用快照值的理由。这一组可以放进正文的脚注或附录。
4. **换成当时版本的卡片，需求匹配份额略降（5.84 → 5.73）。**
   - 文本相似度系数从 11.7 降到 10.7，但仍然很强（z = 23）。
   - 说明快照卡片中有一小部分"选择之后才写上去"的内容，但需求匹配不是由它带来的。
   - 有 benchmark 分数的版本只有 85 个，所以质量组几乎没有变化。
5. **写法建议：** 论文里可以写"用 Internet Archive 回溯选择当时的页面信号、用 git 历史回溯当时的卡片后，流行份额变化不超过 0.2 个百分点，适合/流行比值在 0.061–0.063 之间"。主结果不需要改动。

## 6. 局限

- **只覆盖枢纽市场：** 88% 的首次采纳；长尾候选没有 Wayback 抓取。
- **抓取频率：** 每月 1 次，选择时刻和最近一次抓取最多相差 60 天；有 25% 的候选行没有可用的抓取。
- **门控与已删除的 repo：** 53 个 repo 仍返回 403（Llama 3.2 / 3.3、CodeLlama、SD3-medium、medgemma 等未申请的系列），15 个返回 404（已删除或改名），合计约占首次采纳的 1.4%。它们沿用快照卡片，在数据中标记为 `hist_src=snapshot`。被选行中 97.4% 用到了当时版本的卡片（Meta 审批前为 95.3%；补抓前后的份额差异不超过 0.01 个百分点，旧表在 `results/tables/v2/p26_prev/`）。
- **空 README：** 有 1,740 个历史版本的 README 为空（多数是 repo 早期的提交），这些记为"无文本"。
- **未做的部分：** 只做了点估计，没有做 bootstrap；份额的差异远小于主结果 95% 区间的宽度（约 ±0.4 个百分点）。

## 7. 复现

```
sbatch slurm/cpu.sbatch scripts/p24_wayback.py --targets --cdx --fetch --summary   # 约 36 小时，可续跑；Wayback 限流，每 4 秒一次请求
sbatch slurm/cpu.sbatch scripts/p25_card_history.py --commits --readme --prep     # 门控 repo 需要 ~/.config/acmec/hf_token
sbatch --mem=256G slurm/cpu.sbatch scripts/p25_text.sh
sbatch --mem=192G slurm/cpu.sbatch scripts/p26_hub.py --build
sbatch slurm/gpu.sbatch scripts/p26_hub.py --fit
```
